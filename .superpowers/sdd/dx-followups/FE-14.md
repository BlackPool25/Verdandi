# FE-14 — Ring push/set fail loudly (PRISSUE-68)

## Status: FIXED

## Problem
`Ring.push()` (full buffer) and `Ring.set()` (out-of-range step) hit a bare
`return` — the write vanished with no signal. Callers (`twinStore.ingest`)
could not tell data was lost.

## Fix (`frontend/src/store/ring.ts`, only file touched + new spec)
- `push(v): boolean` / `set(step, v): boolean` — `true` on success, `false`
  on rejection. Rejections increment the counted surface, never silent.
- Counted surface: `dropped` counter (+ `errors` alias), `lastError: string | null`,
  `resetErrors()` (clears counters, keeps data).
- Loud non-finite guard: `NaN`/`±Infinity` rejected + counted (was silently
  coerced by `Float32Array`).
- Strict variants: `pushOrThrow` (RangeError full / TypeError non-finite),
  `setOrThrow` (RangeError range / TypeError non-finite).
- Default path stays non-throwing so the hot ingest loop and the
  render-counter gate (no per-tick chrome renders, badges only) are untouched.
  `twinStore` needed no changes — it ignores the new boolean today and can
  adopt the counter next.

## Test proof (`frontend/src/store/ring.spec.ts`, TDD: 6/6 failed before, pass after)
- push-beyond-cap → `false`, `errors === 1`, `lastError` matches, stored data intact
- out-of-range set → `false`, counted, data intact
- NaN/Infinity → rejected loudly, `length` unchanged
- `pushOrThrow`/`setOrThrow` throw RangeError/TypeError
- success path unchanged; `resetErrors` clears surface, keeps data
