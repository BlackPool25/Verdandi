# FE-11 — Gap/discontinuity rendering in StripChart + EventFeed

## Status: DONE (fixed: YES)

Seek/transport holes previously rendered as continuous charts over
discontinuous data. Both surfaces now render an explicit gap state
(break markers + badge/row) wherever covered steps are non-contiguous.
No SSE changes. No files outside the lane were written.

## Key finding for follow-up wiring (NOT in this lane)

The store/ring lane made `Ring.set` fail-loud: non-finite writes are
rejected, so missing ring slots stay `0` — indistinguishable from legit
`0` readings (e.g. buffer occupancy). Consequence: the `steps` prop is
the ONLY honest gap signal for StripChart in production; zero-sniffing
would be dishonest and was deliberately not implemented. Live wiring
needs a store-side ingested-step accessor (store lane) or a
`steps` feed from the transport lane (`TwinStreamProvider` knows each
ingested `tick.step`; FE-9 owns drop accounting). Until then, badges
render wherever callers pass `steps`; defaults preserve old behavior
(zero false positives).
